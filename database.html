How this "database" works (in plain words)

A real deployed app would store its data on a server, in something like MySQL or PostgreSQL. For this project, we're using the browser's own built-in storage box called localStorage instead — it works the same way, just smaller and simpler, which is perfect for a class project.

Think of localStorage like a small filing cabinet inside your browser. Each drawer has a label (we call it a "key"), like "users" or "expenses". Inside each drawer is a list of records saved as text (in a format called JSON). That list of records is basically the same idea as a table in a normal database — each record is like a row, and the fields inside it (name, email, amount...) are like columns.

Every time you register, add an expense, mark attendance, and so on, the app calls a function that writes into one of these drawers. Refresh the page or come back tomorrow and the data is still there, because localStorage saves it to your computer's disk, not just to memory.
